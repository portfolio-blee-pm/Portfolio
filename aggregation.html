Context & my role

One program, from product to platform to operations

Recyclops ran recycling pickup through local drivers and partners, coordinated by a central platform. ReDyper reconfigured that service into a new model for households and businesses, and it needed a new gig-aggregation platform to run on.

That meant building a product, a platform, an integration layer, a data model, and a launch operation, all at once, while the existing platform was rebuilt underneath live markets.

Problem & constraints

Everything was new at the same time

The hard part wasn't any one piece. It was building all of them in parallel without any one piece blocking the others.

A new service model with no product requirements or readiness criteria
A platform rebuild competing with expansion for the same engineers
Five tools holding launch, dispatch, and billing data, with no system of record
No repeatable launch sequence, and dependencies tracked ad hoc
Key decisions

Three systems-level calls that shaped the program

Run the platform rebuild and the national expansion as one program

Options
(a) Freeze expansion until the rebuild ships · (b) Run them as two programs · (c) Merge both into one delivery plan with shared release sequencing
Chose
One plan: Scrum and Kanban teams working inside a waterfall release schedule
Tradeoff
This added planning overhead and forced hard backlog trade-offs every week. In return, expansion never waited on the rebuild, and no release surprised a market that depended on it.

Integrate the existing tools through their APIs instead of building a new ops platform

Options
(a) Build a custom ops platform · (b) Buy an all-in-one tool · (c) Integrate Monday.com, Jira, Slack, Stripe, and partner systems, with one system of record per field
Chose
Integrate through APIs, with one system of record per field
Tradeoff
We accepted some limits from each vendor's API. In return, Engineering stayed focused on the core platform, teams kept the tools they knew.

Standardize before speeding up

Options
(a) Launch as many markets as fast as possible and fix problems later · (b) Build the framework, gates, and shared data definitions first
Chose
Framework, gates, and definitions first
Tradeoff
The first expansion markets moved more slowly. After that, every launch reused the same sequence, time-to-launch halved, and markets could launch in parallel safely.
Execution

From concept to national scale

Four phases. They overlapped in practice, but each had a clear owner and exit criteria.

Phase 1
Define the product and the platform
Turned the ReDyper concept into a new service configuration and the gig-aggregation platform behind it. Set requirements, readiness criteria, and the plan for rebuilding the platform while it stayed live.
Phase 2
Build the integration and data layer
Specified API data flows and reconciliation rules with Engineering, and built and configured parts of the integration layer myself: workflow automations, webhook integrations, and data scripts. Set schema definitions shared by every market.
Phase 3
Stand up the launch engine
Turned the national expansion strategy into a launch framework that each market could repeat: market sequencing, dependency maps, critical paths, readiness gates, and named workstream owners.
Phase 4
Scale nationally
Ran parallel market launches with go/no-go held at the program level, while scenario and capacity models across 25 markets drove staffing and cost decisions. Then handed each market to steady-state operations.

Retrospective

What I'd do differently

Build the integration layer in month one. Early readiness reviews were manual. Once launch status synced automatically across tools, reviews got faster. I'd build that first, not partway through.

Version the data definitions. When a definition changed partway through, older reports became hard to compare. A simple changelog for definitions would have fixed that.

Standardize the hypercare exit. Handoffs to steady-state operations depended too much on the people who launched each market. A standard exit checklist would have made them cleaner.
