Context & my role

Scaling markets meant scaling data problems

With a few markets, people could reconcile launch status, dispatch, and billing by hand. Past ten markets that broke down: status in Monday.com didn't match Jira, dispatch could drift from which markets were actually live, and billing needed checking against completed jobs.

I owned
Integration requirements, data flows, reconciliation rules, schema definitions, and the reporting each audience needed.
I influenced
Engineering implementation choices and the priority of integration work within the shared backlog.
Partners
Engineering, Operations, Finance, and partner and vendor technical contacts.
Problem & constraints

Five tools, no single source of truth

The issue wasn't missing tools. The tools disagreed with each other, and nobody had defined which one was right for which piece of data.

Launch status kept in parallel in Monday.com and Jira
Dispatch and billing checked by hand against completed work
Each market defined the same metrics differently
Executives saw reports that were days old and assembled manually
Key decisions

Two calls that shaped the integration

Integrate the existing tools instead of building a new platform

Options
(a) Build a custom ops platform · (b) Buy a new all-in-one tool · (c) Integrate the tools teams already used, through their APIs
Chose
Integrate the existing tools
Tradeoff
We accepted some limits from each vendor's API. In return, teams kept the tools they knew, adoption wasn't a risk, and Engineering stayed focused on the core platform rebuild.

Agree on definitions before building dashboards

Options
(a) Build dashboards first and clean up the data later · (b) Settle schema definitions and reconciliation rules first
Chose
Definitions and rules first
Tradeoff
Dashboards arrived later. But once they shipped, executives trusted the numbers, and nobody reopened the definitions in every review.

Retrospective

What I'd do differently

Track how fresh the data is. We could see the data, but not how old it was. A visible "last synced" time on each feed would have made sync failures obvious sooner.

Version the schema definitions. When a definition changed partway through, older reports became hard to compare. A simple changelog for definitions would have fixed that.
